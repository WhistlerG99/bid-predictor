# SageMaker Pipeline Setup for Bid Predictor

The following checklist walks through configuring an end-to-end SageMaker Pipeline
that trains the bid predictor, packages the inference entry point, and performs
batch inference on parquet datasets stored in Amazon S3.

## Prerequisites

1. **Create an S3 bucket** to host training data, model artifacts, and batch
   inference outputs (for example, `s3://my-bid-predictor`).
2. **Upload your parquet training data** to a prefix such as
   `s3://my-bid-predictor/data/train/`.
3. **Build a training image** (or reuse the provided one) with the repository
   contents copied to `/opt/ml/code`. The image must include the dependencies
   from `requirements.txt` plus `boto3` (already available in SageMaker Python
   images).
4. **Create an execution role** with permissions for SageMaker, S3 read/write,
   and CloudWatch Logs.

## Define the Pipeline Steps

1. **Training step (`TrainingStep`)**
   - Use a SageMaker `SKLearn` or `Estimator` object that runs `train.py`.
   - Point the input channel `"train"` at the training data prefix from the
     prerequisites section.
   - Configure output artifacts to land in your bucket, for example
     `s3://my-bid-predictor/artifacts/`.
   - Pass any CatBoost hyper-parameters or feature configuration overrides via
     the estimator's `hyperparameters`.

2. **Model creation step (`ModelStep`)**
   - After the training job completes, create a SageMaker `Model` using the
     training output location.
   - Ensure the model's `ModelData` points to the `model.tar.gz` generated by
     training. The modified `train.py` saves `pipeline.joblib` along with
     `code/inference.py`, making the tarball self-contained for inference.
   - Optionally register the model in the SageMaker Model Registry for reuse.

3. **Batch inference step (`ProcessingStep`)**
   - Instantiate a `ScriptProcessor` (or `SKLearnProcessor`) with the same image
     used for training.
   - Provide the trained model artifacts as an input channel pointing to the
     model tarball from the model step.
   - Supply the parquet dataset to score via another input channel or by passing
     the S3 URI as a pipeline parameter.
   - Set the entry script to `inference.py` and include arguments:
     ```python
     [
         "--input-s3-uri", input_data_s3_uri,
         "--output-s3-uri", output_predictions_s3_uri,
     ]
     ```
   - The script automatically loads `pipeline.joblib`, scores each parquet file,
     and uploads predictions to the specified output prefix (and to
     `SM_OUTPUT_DATA_DIR` for pipeline caching).

4. **Condition or callback steps (optional)**
   - Add quality gates (for example, verifying AUC from the training step) using
     `ConditionStep` components before triggering batch inference.
   - Notify downstream systems via `CallbackStep` or AWS EventBridge if required.

## Parameterizing the Pipeline

1. Define pipeline parameters for:
   - Training data S3 URI.
   - Feature configuration path (if different from defaults).
   - Batch inference input S3 URI.
   - Batch inference output S3 URI.
2. Inject these parameters into the estimator and processor arguments so the
   pipeline can be reused across environments (dev/staging/prod).

## Executing the Pipeline

1. Create or update the pipeline definition using the SageMaker Python SDK.
2. Start the pipeline execution with parameter values specific to the run.
3. Monitor progress in the SageMaker Console; logs stream to CloudWatch.
4. Retrieve batch inference outputs from the configured S3 prefix (parquet
   files with prediction columns `prediction` and `acceptance_probability`).

## Maintenance Tips

1. Rebuild the Docker image when dependencies change or when `inference.py`
   receives updates.
2. Version-control pipeline definitions alongside this repository to track
   infrastructure changes.
3. Use SageMaker Model Registry or tags on pipeline executions to capture model
   lineage and metadata for audits.
